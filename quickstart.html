Quick Start

From install to your first accessibility review in a few minutes, in the AI coding tool you already use. New to all of this? Start here.

1 Install Accessibility Agents

Install it as a plugin. That brings the skills, the edit gate (on clients that support hooks) and the MCP server in one step. You need Node.js 22 or later.

Claude Code, in a session
/plugin marketplace add Community-Access/accessibility-agents /plugin install accessibility-agents@community-access
GitHub Copilot CLI
copilot plugin marketplace add Community-Access/accessibility-agents copilot plugin install accessibility-agents@community-access
Gemini CLI
gemini extensions install https://github.com/Community-Access/accessibility-agents

For VS Code, Codex, Antigravity or the MCP server on its own, see every install option.

2 Describe what you are working on

You do not need to name a skill. Say what you want in plain words, and one of six entry points routes it to the right specialists:

  • “Review this modal for accessibility”: accessibility-lead picks the modal, keyboard and ARIA specialists, runs them, and tells you whether it ships.
  • “Audit the whole site”: web-accessibility-wizard asks four questions, runs every domain and writes WEB-ACCESSIBILITY-AUDIT.md.
  • “Check these PDFs”: document-accessibility-wizard scans each file and writes a scored report.
  • “Fix the markdown in docs/”: markdown-a11y-assistant shows you the fixes it wants to make, and waits for you.

You can also call a skill by name: /accessibility-lead in Claude Code, Copilot and VS Code, or $accessibility-lead in Codex. Specialists such as /aria-specialist and /contrast-master are in the slash menu too.

3 Meet the edit gate

Once installed, an edit to a user-facing file (HTML, JSX, Vue, Svelte, CSS, templates) is refused until accessibility-lead has finished its review in the session. That refusal is the point, not a fault: let the review run, then the edit goes through. Build output, tests, stories and dependencies are exempt.

4 Read the report

Every audit report has the same seven sections, written by a script from the specialists’ findings rather than typed by the model: what was audited, a score out of 100 with a grade, the severity breakdown, each finding with its WCAG criterion, location and fix, remediation priorities, next steps, and what changed since the last report.

What’s next?

  • Documentation: the skills catalog, MCP tools, scanning guides and configuration

Automated review is a first pass, not a verdict. Test with NVDA, JAWS, VoiceOver, TalkBack and a keyboard before you ship.
